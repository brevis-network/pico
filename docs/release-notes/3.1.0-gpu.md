# Pico 3.1.0-gpu.1 release notes

Version `3.1.0-gpu.1`, tag `v3.1.0-gpu.1`, on the `gpu` branch. A preview of Pico 3.1: Pico 3.0
with a GPU prover. The CPU-only 3.0 release line stays on `main` (`v3.0.x`).

## Highlights

- **GPU prover.** The RISCV, CONVERT and COMBINE phases prove on NVIDIA GPUs: the `cuda-mle`
  device backend runs LogUp-GKR, zerocheck, stacked reduction and WHIR, and `gpu-api` generates
  the chips' traces. The CUDA kernels are in [pico-gpu](https://github.com/brevis-network/pico-gpu).
- **Multi-card and two-host proving.** `distributed-vm`'s `mle-single-node` proves on one or more
  cards of one host (`single_node_mle.sh <cards>`), or split across two hosts
  (`two_machine_mle.sh`).
- **Ethproofs entry points.** `mle-ethproofs-single-node` proves Ethereum blocks for the ethproofs
  service, and `mle-ethproofs-vk-bundle` exports the verifying keys it needs.

## Compatibility with 3.0

The proof system and its parameters are those of `v3.0.0`: the verifying-key whitelist and its
root (`vm/src/mle/shape_vk_bins/`), the RISC-V constraint surface, the soundness manifest and the
verifier contracts are unchanged. The guest SDK, `pico-prover` and the CLI have the 3.0 interfaces.

## Requirements that change from 3.0

- Every crate that depends on `pico-vm`, `pico-cli` and `pico-sdk` included, needs the CUDA
  Toolkit (`nvcc`) on x86-64 Linux to build. macOS is not supported on this branch; use `v3.0.0`.
- Running the emulator needs an NVIDIA GPU and its driver, also to execute a program or prove it on
  the CPU through `pico-prover` or `cargo pico prove`: the emulator's event buffers are CUDA
  pinned memory. Without a device it stops with `Failed to create event buffer: ErrorNoDevice`.
- The CLI takes Pico from the `v3.1.0-gpu.1` tag for `--aot`. `cargo pico new` falls back to the
  template's `main` branch, which is written for 3.0, and says so.
