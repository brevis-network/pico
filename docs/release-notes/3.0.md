# Pico 3.0 release notes

Version `3.0.0`, tag `v3.0.0`.

## Highlights

- **New proof system.** Pico now proves with a multilinear (MLE) STARK on the KoalaBear field —
  LogUp-GKR, ZeroCheck and WHIR — through five phases: RISCV → CONVERT → COMBINE → EMBED → WRAP.
  The WRAP output is proved with Groth16 on BN254 for on-chain verification.
- **CPU prover.** The prover in this release runs on the CPU.
- **New host crate, `pico-prover`.** It replaces the prover client that lived in `pico-sdk`.

## Breaking changes

Pico 3.0 is not compatible with 2.x proofs, keys or verifier contracts. In short:

- 2.x proofs cannot be read or verified; re-prove with 3.0. Program ids change.
- The on-chain verifier is new: `verifyPicoProof(bytes32, bytes, uint256[12])` (was
  `uint256[8]`). Redeploy it.
- Host code moves from `pico_sdk::client` to `pico-prover`.
- `pico-sdk` drops the `bb`, `m31` and `aot` features (`kb` is a no-op).
- `cargo pico prove`: `--elf` is required, `--input` is typed and repeatable, the default output
  directory is `./pico_out`, and the default phase is COMBINE.
- `cargo pico prove --evm` runs gnark from a binary or an image you build (`PICO_GNARK_BIN` /
  `PICO_GNARK_IMAGE`) and needs whitelist mode.
- Rust `nightly-2026-09-27` and guest toolchain `pico-ae9fd31`; rerun `cargo pico install`.

The [migration guide](../migration-2.x-to-3.0.md) lists every change with its replacement.

## New

- `pico-prover`: `Prover::prove` returns a proof that is already verified and bound to the guest's
  committed bytes; `prove_to` stops at any phase; `execute` emulates without proving;
  `Proof::write`, `ProofArtifact::read` and `Prover::verify_artifact` move a proof between
  processes; `prove_evm` returns the gnark inputs for the on-chain proof.
- `cargo pico execute`, `cargo pico aot`, and `--aot` on `prove` and `execute` for emulation with
  ahead-of-time compiled guest code.
- `cargo pico prove --phase riscv|convert|combine|embed|wrap`, and typed inputs
  (`--input u32:100`, `0x<hex>`, `file:<path>`).
- `cargo pico new` clones the template release that matches the CLI version (`--template-ref` to
  override).
- The Solidity verifier (`PicoVerifier`, `IPicoVerifier`) ships in [`contracts/`](../../contracts)
  with Foundry tests.

## Security

Pico 3.0 targets 100 bits of provable round-by-round soundness under the random-oracle model,
through the recursion root; the on-chain Groth16 step is held to BN254's security level. This is a
computed bound, not a formal verification.

The verifier shipped in `contracts/test/dev` comes from a test setup. A deployment needs keys and a
verifier from a real setup ceremony.

A security review of Pico 2.x by Sherlock is available in [`audits/`](../../audits); it predates and
does not cover the 3.0 proof system.

## Removed, no replacement

- The BabyBear and Mersenne31 fields, and FRI-based proving.
- The COMPRESS phase.
- `cargo pico prove --fast` (use `--phase riscv`, which is full-security) and `--field`.

## Platforms and support

Prebuilt guest toolchains exist for `aarch64-apple-darwin` and `x86_64-unknown-linux-gnu` only. See
the [support matrix](../support-matrix.md).
